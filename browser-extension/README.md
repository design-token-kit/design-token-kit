# Design Token Kit Inspector

Chromium DevTools extension that shows which design tokens style the element
selected in the Elements panel.

## Install

* Build: `npm run build --workspace @design-token-kit/browser-extension`.
* Open `chrome://extensions`, enable developer mode, click "Load unpacked" and
  pick `browser-extension/dist`.

## Use

* Open DevTools, the Elements panel, and the "Tokens" pane next to "Styles".
* Select an element: the pane lists its properties with token chains.
* Click a link to copy the token path.
* Generate the CSS with `dtokens convert --css-token-map` to get a CSS token
  map.
  With the map, the pane shows token paths and descriptions instead of custom
  property names.
  Without a map, a click copies the custom property name.
* Load the map in the pane: click "Open file" and choose the map file, or
  enter the absolute map URL and click "Use URL".
  The pane keeps the content of a chosen file, so later changes to the file
  are not picked up until it is chosen again.
  A map file larger than 5 MB is rejected.
* The pane fetches the map URL again after each page load.
  It sends the cookies of the map URL's site, but only for https URLs.
  Redirects are refused, so the cookies do not follow the request elsewhere.
  The URL must use http or https.
* The map is remembered per site origin.
  Click "Remove" to forget the map of the current site.
* Maps are kept in the extension storage, which holds about 10 MB for all
  sites together.

## Limitations

* Requires Chrome 118 or later.
* Chrome shows a debugging bar while the pane is open, because the extension
  reads styles over the DevTools protocol.
* A color property reference such as `{primitive.color.blue.components}` is
  converted to a value, so its chain ends there.
* A build step that replaces `var()` with values removes the chains.
* Pseudo-elements and closed shadow roots are not inspected.
* Pages without a real origin, such as `file:` and `data:` pages or sandboxed
  frames, share one stored map.
* Only the top frame is inspected.
  Elements inside iframes are not.
* CSS-wide keywords (`inherit`, `initial`, `unset`) in a value are not
  followed.
  The chain ends at the keyword.
* The theme of a link is recognized only from `[data-theme="..."]` selectors,
  as generated by `dtokens convert`.
* A shorthand and its longhands are traced separately.
  So own `font` and an inherited `font-size` may both be listed.
* `!important` is applied by declaration order.
  This is wrong for important declarations inside cascade layers.
* A custom property whose value combines several references, such as a shadow
  or border token, ends the chain at that value.
  Its nested references are not followed.
